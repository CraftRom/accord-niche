# ACCORD NICHE v1.11.2 — діагностика та виправлення

Dashboard **1.80.2**. Повний проєкт на основі v1.11.1; зміни стосуються сайту, керування блогом і відповідних перевірок.

## Підтверджені та виправлені помилки

1. **Статті dashboard після зміни фільтра.** Під новим станом публікації залишалися старі картки. Результати тепер прив’язані до вкладки, пошуку, фільтра та сторінки; до отримання відповідної відповіді показується завантаження.
2. **Черга модерації після зміни фільтра.** Навіть після помилки нового запиту були доступні дії зі старої черги. Старі коментарі та лічильники приховуються при зміні відбору. Помилка не видається за порожню чергу. При збої оновлення того самого відбору завантажені дані залишаються з явним повідомленням помилки.
3. **Пагінація публічного блогу.** Перехід на наступну сторінку застосовував текст, який користувач лише почав вводити у пошук. Пагінація тепер зберігає застосований запит з URL; новий пошук застосовується кнопкою «Знайти» і починається з першої сторінки.
4. **Історія покупок: запізніла сторінка.** Якщо під час завантаження додаткових замовлень натиснути «Оновити», стара відповідь могла дописати замовлення до нової історії та повернути неправильний стан кнопки. Додаткова сторінка приймається тільки для поточного покоління даних. Повторні одночасні запити блокуються; демонтування компонента скасовує застосування результатів.
5. **Історія покупок: помилковий порожній стан.** При початковому збої API поруч із помилкою відображалося «Історія покупок поки порожня». Порожній стан тепер можливий лише після успішного отримання історії. Кнопка повторного оновлення залишається доступною.
6. **Контраст вкладок блогу dashboard.** Білий текст на золотистому фоні не забезпечував контраст 4,5:1. Активна вкладка використовує світлий акцент системної теми й темний текст, узгоджені з навігацією. Перевірка використовує CSS production-збірки та фактичну змінну кольору теми.

П'ять функціональних збоїв відтворено новими тестами до зміни коду; окремо перевірка контрасту не проходила до виправлення стилю. Додано також позитивний сценарій збереження тієї самої черги при тимчасовому збої оновлення.

## Візуальний огляд і межі перевірки

16.11.2026 відкрито робочий магазин у браузері: головну сторінку, каталог, порожній кошик і блог. На перевіреному desktop-екрані основні блоки читабельні; кошик відкривається, Escape закриває його. Форма входу dashboard доступна через HTTPS.

Публічний каталог на момент огляду повертав нуль товарів, блог — порожній список. Це не доводить, що вся БД порожня: без адміністративного доступу не перевірено наявність прихованих або неопублікованих записів. Реальна покупка на робочому сайті не створювалася. Сценарії з товарами, замовленнями, статтями, затримками та помилками API перевірено автоматизовано на ізольованих тестових даних.

Вхід у робочий dashboard не виконувався: візуально перевірена лише форма входу. Авторизовані розділи перевірені DOM-тестами. Мобільні розміри в реальному браузері в цьому проході не перевірялися. Візуальний огляд робочого сайту не є перевіркою розгортання нової збірки: наведені виправлення ще не встановлено на VPS.

## Оновлення

Нових міграцій немає. Backend, Mini App, TLS, конфігурації доменів і розгортання не змінені відносно v1.11.1. Збережені окремі імена `accord-website`, `accord-miniapp`, `accord-dashboard` та сумісність зі спільним edge ELFAR.

Розпакуйте повний архів у `/opt/accord-niche`, зберігши поточний `.env.domains` та дані. Від root:

```bash
python3 /opt/accord-niche/scripts/connect_elfar_edge.py
```

Після оновлення перевірте версію dashboard 1.80.2, зміну стану статей і черг коментарів, пагінацію історії та наявність опублікованих товарів у каталозі.
