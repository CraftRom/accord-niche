# ACCORD NICHE v1.20.0 — серверні SEO-метадані сайту

Website **1.4.0**. Етап **6** плану аудиту, друга частина (SEO). Міграцій БД немає, head `f4c8e2a17d59`.

## Проблема

Сайт — односторінковий застосунок: кожна адреса віддавала той самий `index.html` з одним заголовком і описом. Пошукові боти й прев'ю в Telegram, Viber, Facebook, які не виконують JavaScript, бачили однакову картку для всіх ароматів і статей. Канонічних адрес, структурованих даних, `sitemap.xml` і `robots.txt` не було.

## Що змінено

- **Метадані на сервері.** Nginx сайту вставляє в `<head>` теги для конкретної адреси через SSI-запит до API (`/api/public/seo/head`):
  - **аромат** `/aroma/<id>`: заголовок із брендом, назвою, об'ємом і ціною, опис, `og:*`, `twitter:card`, канонічна адреса, JSON-LD `Product` з ціною в UAH і наявністю;
  - **стаття** `/blog/<slug>`: заголовок, опис, `og:type=article`, обкладинка, JSON-LD `BlogPosting`. Старий slug вказує канонічну адресу на поточний;
  - **розділи** (головна, каталог, набори, бренди, блог, «Як це працює») мають власні заголовки й канонічні адреси;
  - **оформлення, кабінет, сторінка успіху, приховані/неопубліковані/неіснуючі товари й статті** отримують загальні теги й `noindex`.
- **Безпека.**
  - Використовуються лише опубліковані дані, той самий публічний набір, що бачить покупець (включно з правилом прихованих категорій).
  - Усе HTML-екрановано; JSON-LD не може закрити свій `<script>`.
  - Зображення лише з того самого сайту або за `https`; протокол-відносні та `javascript:` адреси відкидаються.
  - Внутрішня адреса `/__seo_head` ззовні нічого не віддає.
- **Стійкість.** API відповідає з тайм-аутом 3 с. Якщо API повільний чи недоступний, сторінка все одно віддається з резервними тегами з `index.html`: без помилок у HTML і без дубля `<title>`.
- **`/sitemap.xml`** (опубліковані SKU, розділи, статті з `lastmod`) і **`/robots.txt`** (закриває оформлення, кабінет і API та вказує на sitemap).
- Під час переходів усередині сайту заголовок вкладки аромату теж оновлюється.

## Перевірено

- **Справжній Nginx з SSI і справжній API** на тимчасовій SQLite: `qa/qa_accord_seo_nginx.py`, **15/15**. Перевірено:
  - заголовок і екранування;
  - JSON-LD;
  - канонічні адреси, зокрема для старого slug;
  - noindex для прихованих сторінок;
  - sitemap і robots;
  - закриту внутрішню адресу;
  - роботу при вимкненому API.
- `qa_accord_nginx_domains.py`: ізоляція доменів **11/11** зі зміненим конфігом.
- `backend/tests_accord` з реальною PostgreSQL 16: **417 passed**, з них новий `test_seo.py` — 16.
- Повний `backend/qa/run_all.sh` у мережевій ізоляції.
- Сайт: build і **42** JS-тести.
- `qa_accord_upload_limits.py` локально не запускався: потрібен nginx ≥ 1.25 (директива `http2`), тут 1.24.
