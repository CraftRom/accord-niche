# ACCORD NICHE v1.17.0 — готовність модулів і обслуговування даних

Dashboard **1.85.0**. Етапи **3–4** плану аудиту: A04, A09, A11, A13. Етап A10 (матриця прав) і A08 (видимість каталогу) закрито у v1.16.0.

## Що змінено

- **A04 — «увімкнено» ≠ «працює».** Планувальник, Telegram-бот і maintenance-виконавець подають heartbeat у спільний том (`/data/heartbeats`, лише назва, збірка, pid і час). Новий `GET /api/system/modules` (адміністратор) показує для кожного модуля один стан: «Працює», «Немає виконавця», «Не налаштовано», «Вимкнено». Охоплено заплановані розсилки, щоденні копії, обслуговування даних, копії з панелі, бота, SalesDrive, домени промосторінок і SMS-підтвердження.
- Панель: картка «Стан модулів» на сторінці налаштувань; на сторінці розсилок — попередження, якщо планувальник не запущений (заплановані розсилки не стартують). Підказка містить точну команду запуску профілю `workers`.
- **A13 — готовність релізу.** `GET /api/system/readiness` (лише системний адміністратор): збірка, ревізія БД проти Alembic head у коді, доступність БД (затримка) і Redis, heartbeat виконавців і перелік проблем. Кнопка «Перевірити готовність релізу» в тій самій картці. Публічний `/api/health` лишився мінімальною liveness-перевіркою без деталей.
- **A09 — промодомени без контролера.** Без `PROMO_CONTROLLER_TOKEN` стан домену повертається як відомий стан «не налаштовано» (200) замість постійного 503 на кожну сторінку; підключення — зрозуміла відмова 409; відключення просто знімає публікацію. Редактор, перегляд і публікація працюють як раніше.
- **A11 — прострочені токени.** Щоденне обслуговування видаляє прострочені сесії сайту й панелі та одноразові коди прив’язки Telegram пачками по 1000. Клієнти, акаунти, зв’язки ідентичностей та історія не змінюються; повторний прохід безпечний. Нові індекси за `expires_at` (міграція `e2a6c4f81b37`).

## Оновлення

Нова адитивна міграція: head **`e2a6c4f81b37`**. Звичайне оновлення shared edge, від root:

```bash
python3 /opt/accord-niche/scripts/connect_elfar_edge.py
```

Після оновлення відкрийте «Налаштування → Стан модулів». Якщо там «Немає виконавця» для планувальника чи бота, запустіть потрібний профіль, наприклад:

```bash
cd /opt/accord-niche
bash deploy/domains.sh --docker-edge --profile workers up -d scheduler
bash deploy/domains.sh --docker-edge --profile bot up -d bot
```

Реальний стан VPS цим пакетом не перевірявся.
