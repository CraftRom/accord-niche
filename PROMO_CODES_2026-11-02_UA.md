# Промокоди — 02.11.2026

Dashboard 1.76.0 · API 1.27.0 · Mini App 2.26.4 · бот 1.19.1.

## Форма та керування

- Створення й редагування коду, відсоткова або фіксована знижка.
- Мінімальна сума замовлення, загальний ліміт і кількість використань одним клієнтом.
- Порожній загальний ліміт означає необмежену кількість; порожня дата — безстроковий код.
- Дата завершення включає весь вибраний день за Europe/Kyiv, незалежно від часового поясу браузера. Незмінена дата під час редагування зберігає точний попередній timestamp.
- Активність, генерація коду, підсумок умов, пошук, фільтр статусів, копіювання та дублювання. Копія починає діяти лише після явного ввімкнення.
- Дія на весь каталог або вибрані категорії з їхніми підкатегоріями. Порожній вибір у режимі категорій не дозволяє зберегти форму. Збій завантаження категорій має повторну спробу.
- Адаптивна форма, власний скрол і доступні кнопки внизу. Виправлено перекриття форми бічним меню на ПК.

## Перевірки та розрахунок

Код нормалізується на сервері: пробіли по краях прибираються, регістр — верхній; 2–32 символи, без внутрішніх пробілів і керівних символів. Дублікати під час створення та перейменування повертають 409; помилка унікальності БД відкочується без пошкодження сесії.

Відсоткова знижка має бути більше нуля та не перевищувати 100%. Грошові поля підтримують до двох знаків після коми та межі Numeric(12,2). Ліміти — додатні цілі числа. API повторює ці перевірки незалежно від форми. Невдала відповідь сервера не скидає введені значення; повторне натискання під час збереження не надсилає другий запит.

Для промокоду на категорії знижка рахується тільки від відповідних товарів. Фіксована знижка не перевищує їхньої вартості. Мінімальна сума перевіряється за всім замовленням. Вітрина, бот і транзакційне оформлення використовують спільні правила; під час оформлення повторно перевіряються категорії та сума знижки.

## Оновлення сервера

1. Зробіть резервну копію бази та файлів чинного розгортання.
2. Оновіть вихідні файли з повного архіву.
3. Перед запуском нового API й бота виконайте стандартні міграції: `alembic upgrade head` з каталогу `backend` у середовищі застосунку. У Docker використовуйте чинний сценарій розгортання, який запускає міграції.
4. Перебудуйте та перезапустіть API, бот і dashboard за вашим чинним сценарієм деплою. Зібрана панель також міститься в `dashboard/dist`.

Нова міграція: `fa3d7b2e1c90`, попередня: `f9b6d4e20c83`. Колонка `promo_codes.category_ids` отримує `[]` для старих записів: ці коди залишаються чинними для всіх товарів.

Новий dashboard надсилає календарну дату через `expires_on`; сервер зберігає її у чинному `expires_at`. Довільний timestamp `expires_at` і далі підтримується з обов’язковим часовим поясом. API та панель потрібно оновлювати разом.
