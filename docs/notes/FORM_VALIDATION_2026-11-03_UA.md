Продовжено перевірку українських текстів панелі за фактичною поведінкою
системи. Виправлено суперечності в умовах збереження форми, підказці
до фото товару й описі доступу менеджера.

## Що виправлено

| Ділянка | Було | Стало |
| --- | --- | --- |
| Створення облікового запису | Кнопка ставала доступною з паролем на 8 символів, хоча сервер вимагає 12. | Форма перевіряє довжину від 12 до 128 символів перед запитом. |
| Заміна пароля | Непорожнє ім’я дозволяло зберегти закороткий новий пароль. | Новий пароль перевіряється незалежно від імені. Порожнє поле при редагуванні залишає чинний пароль. |
| Зміна ролі | Обліковий запис без імені не можна було зберегти без нового пароля. | Роль можна змінити, залишивши ім’я та поле нового пароля порожніми. |
| Логін та ім’я | Форма не пояснювала всіх обмежень. | Логін: 3–64 символи, латиниця, цифри, крапка, дефіс або підкреслення. Ім’я необов’язкове, до 128 символів, без NUL. |
| Збереження | Повторне натискання могло запустити ще один запит. Діалог можна було закрити під час запиту. | Синхронне блокування повторного запиту; поля й скасування заблоковані до відповіді сервера. |
| Підказка до фото товару | Зазначено ліміт 5 МБ. | Зазначено 8 МБ відповідно до чинного завантажувача та API: 8 × 1024 × 1024 байтів. |
| Права менеджера | Текст обмежував доступні налаштування лише реферальною програмою. | Вказано бонуси, реферальну програму та знижку від суми — саме ці модулі дозволяє сервер. |
| Помилки пароля | Повідомлення стверджували, що певні паролі підбираються за секунди або миттєво. | Повідомлення пояснюють причину відмови: лише цифри, поширений пароль або не більше двох різних символів. |

Підписи полів пов’язані з відповідними елементами вводу; підказки доступні
через `aria-describedby`, помилки після взаємодії — через `aria-invalid`.
Повідомлення після створення називає обліковий запис незалежно від вибраної
ролі. Опис адміністратора уточнює керування платіжними реквізитами й
обліковими записами.

Пароль передається без обрізання пробілів, зміни регістру чи підстановки
символів. Довжина в браузері рахується за Unicode code points, як Python
`len()`, а не за одиницями UTF-16. Сервер і далі перевіряє числові,
поширені та повторювані паролі; ці перевірки не дублюються словником у браузері.

## Що збережено

Серверна політика паролів, PBKDF2, кількість ітерацій, сіль, правила входу
та перелік дозволених налаштувань не змінювалися. Порівняння Python AST
з попереднім випуском підтвердило: у `passwords.py` і маршруті налаштувань
змінено лише чотири повідомлення. Схеми API, SQL, авторизація й фінансові
розрахунки залишилися без змін.

Ліміт завантаження зображень теж не змінювався: виправлена лише підказка
до фото товару. Окремі обмеження зображень розсилки залишаються чинними.
