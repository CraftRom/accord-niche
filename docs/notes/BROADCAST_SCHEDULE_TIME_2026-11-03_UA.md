Виправлено передчасний запуск запланованої розсилки. API округлював
вибраний час вниз до цілої години, хоча чинний планувальник перевіряє
чергу приблизно кожні 15 секунд. Наприклад, вибрані **12:37** ставали
**12:00**. Якщо поставити таку розсилку в чергу о 12:10, вона могла
почати надсилання вже під час найближчої перевірки.

## Виправлення

| Ділянка | Поведінка після оновлення |
| --- | --- |
| Форма розсилки | Час можна вибрати з точністю до хвилини. Початкове значення лишається наступною цілою годиною; це лише зручне значення за замовчуванням. |
| API створення та планування | Вибраний момент переводиться в UTC без округлення. API також зберігає секунди й частки секунди, якщо їх передав клієнт. |
| Час у минулому | Відхиляється і при створенні, і при переплануванні, зокрема час, що вже минув у поточній годині. Невдале перепланування не змінює чинний запис. |
| Повернення часу | `scheduled_at` повертається з явним часовим поясом UTC, зокрема після читання зі SQLite. Браузер більше не має трактувати UTC без позначки поясу як місцевий час пристрою. |
| Підказки й інструкція | Замість застарілого опису щогодинного запуску вказано поточний інтервал перевірки та запуск не раніше вибраного часу. Пояснено дію тихих годин і ручного надсилання. |
| Підрахунок аудиторії в інструкції | Вказано автоматичне оновлення підрахунку; результат надсилання кожному клієнту доступний у журналі. |

Узимку вибрані **12:37 за Києвом** передаються як **10:37 UTC**.
Улітку враховується відповідний зсув часового поясу пристрою.
Тихі години перевіряються за часовим поясом магазину.

Час перевірки черги не є гарантією доставки за 15 секунд. Тихі години,
навантаження й збої сервісів можуть відкласти запуск. Ручні дії
«Надіслати зараз» і «Продовжити», як і раніше, запускають надсилання
без очікування тихих годин. Правила цих дій не змінювалися.

## Сумісність та оновлення

Раніше заплановані записи залишено без змін. Якщо попередня версія вже
відкинула хвилини, вихідний час відновити з бази неможливо. Для такого
запису натисніть **«Зняти з черги»**, відкрийте чернетку через
**«Редагувати»** та заплануйте її на потрібний час знову.

Майбутні значення на цілу годину лишаються коректними. Для старих API-клієнтів
час без позначки поясу, як і раніше, означає UTC. Поля запитів та відповідей
збережені. Зміна поведінки: минулий момент у поточній годині тепер дає
HTTP 422 замість негайного запуску.

Планувальник, SQL-вибірка черги, блокування виконавців, журнал результатів,
повтори, тихі години, обмеження зображень і формати повідомлень не
змінювалися. Авторизація, фінансові правила й Mini App також не змінювалися.

Окремий тест перевіряє справжню SQL-чергу з контрольованим годинником:
за одну мікросекунду до вибраного моменту немає жодної спроби надсилання;
у вибраний момент тестові отримувачі обробляються один раз. Наступна
перевірка черги не повторює завершену розсилку. Наявні тести тихих годин,
відновлення та конкурентного захоплення розсилки також пройшли.

Використовувалися ізольовані тестові бази й підміни Telegram; реальним
клієнтам повідомлення не надсилалися. Production PostgreSQL і робочі
облікові записи в цій перевірці не використовувалися.

У повний архів включено всі попередні зміни. Оновлення на робочому VPS
ще не встановлено; для застосування потрібні нові API та збірка панелі.
