# ACCORD NICHE v1.11.0 — dashboard для онлайн-магазину

Оновлено dashboard до **1.80.0**. Панель працює з єдиними товарами, покупцями та замовленнями сайту, Mini App і бота. Наявну фінансову аналітику доповнено окремим оглядом поточної роботи магазину.

## Робочий огляд

Навігацію згруповано за задачами: **Продажі**, **Вітрина й контент**, **Маркетинг**, **Керування**. Назва панелі — ACCORD NICHE. Права збережено: менеджеру недоступні налаштування, команда, блог та інфраструктура; адміністратору не відкриваються системний журнал і резервні копії.

Блок **Робота магазину зараз** показує з БД:

- нові та відкриті замовлення, замовлення без накладної;
- найстаріші нові замовлення з контактом, сумою та каналом;
- доступні варіанти товарів, залишок до 3 шт., відсутні товари;
- активні товари без ціни та без фото;
- відкриті замовлення за каналами: сайт, Mini App, бот, невизначений;
- кількість коментарів на модерації — лише адміністративним групам.

Кожен лічильник веде до відповідного відбору. Лічильники та списки використовують спільні серверні умови. Відмови й повернення виключені з робочих черг. Відкритими вважаються етапи «Нове», «Прийняте», «Оплачене», «Відправлене»; завершені та скасовані замовлення виключені. Черга без накладної охоплює нові, прийняті й оплачені записи без ТТН — вона не означає автоматичної готовності до відправлення.

Черги не залежать від обраного місяця фінансового звіту. У збереженому звіті закритого місяця поточний блок не показується, щоб не змішувати історію з теперішнім станом. Опитування працює кожні 30 секунд лише у видимій вкладці. Є ручне оновлення, час отримання даних і явна помилка замість вигаданих значень.

## Замовлення та канали

Додано серверні фільтри за каналом, робочою чергою, оплатою й доставкою. Відбір і сторінка зберігаються в адресі. Загальна кількість і список обчислюються з однаковими умовами. Пошук підтримує номер замовлення, ПІБ, телефон із форматуванням та номер накладної.

Канал продажу відокремлений від рекламного джерела. Наприклад, `source=google` і `channel=accord_website` означають замовлення сайту. Для нових покупок канал установлює відповідний серверний сценарій; рекламна мітка його не підмінює. Старі записи класифікуються за збереженим джерелом, сесією Mini App та резервними UTM із CRM. Якщо походження визначити неможливо, воно лишається невизначеним.

Виправлено втрату `channel` при перетворенні даних БД у відповідь API, включно з резервними UTM із CRM. Тепер бейджі в панелі узгоджені із серверними лічильниками та відборами.

Виправлення списку, швидкого перегляду та картки замовлення:

- ПІБ не повторює прізвище й по батькові у старому та новому форматах запису.
- Службовий від’ємний Telegram ID вебпокупця не видається за контакт.
- Відсутній спосіб оплати не підмінюється переказом на картку.
- Нове локальне замовлення без CRM не називається історичним лише через відсутність інтеграції.
- Для вебпокупця показано зв’язок телефоном і перегляд статусу в профілі. Telegram-чат не пропонується як доступний канал для службового вебкористувача.

## Товари та залишки

Усунено обмеження перших 500 товарів у dashboard. Пагінація, сортування й фільтрація виконуються сервером над усім каталогом. Після повернення з картки товару зберігаються відбір, сортування, сторінка та її розмір. Масові дії працюють із явно вибраними товарами поточної сторінки.

Додано відбори: **у наявності**, **до 3 шт.**, **немає в наявності**, **активні без ціни**, **без зображення**, **приховані**. Зміна залишку чи видимості оновлює відбір, якщо товар перестав відповідати його умовам. За збою завантаження індикатор завершується, доступні повторення та скидання фільтрів.

Активний товар із нульовою ціною більше не позначається доступним для покупки. У картці товару видно стан публікації: прихований, опублікований без залишку або доступний для покупки. Показано відсутність фото чи опису; для опублікованого товару є посилання на його варіант на сайті. Фото та опис не оголошуються обов’язковою умовою публікації, якщо сервер їх не вимагає.

## API та сумісність

Новий захищений `GET /api/orders/operations` повертає робочий огляд. Модераційні дані відсутні у відповіді менеджеру. Нові параметри `/api/orders`: `channel`, `queue`, `payment_method`, `delivery_method`.

`GET /api/catalog/products` підтримує `paginated=true`, `limit`, `offset`, `sort`, `inventory`; у цьому режимі повертаються `items` і `total`. Старий режим масиву збережено для наявних клієнтів. Нових таблиць і міграцій немає; поточний head — `c04b19a7e230`.

## Оновлення

Розпакуйте повний архів у `/opt/accord-niche`, зберігши `.env.domains` та дані. Від root:

```bash
python3 /opt/accord-niche/scripts/connect_elfar_edge.py
```

Конфігурації доменів, TLS, Compose, сценарії розгортання та міграції не змінено. Розділення мереж і імен ACCORD/ELFAR збережене.

## Перевірки

- **315 Python-тестів і 14 subtests**: регресії, SQL/API-фільтри, узгодженість лічильників і списків, каталог понад 500 товарів, права та збереження каналу в API.
- Класифікацію каналів, робочі черги й резервні UTM із CRM перевірено виконанням SQL на ізольованому **PostgreSQL 16**.
- **69 JS/DOM-перевірок**: 38 для dashboard, 31 для сайту. Нові сценарії охоплюють робочий огляд, роль менеджера, помилки, комбіновані фільтри, вебконтакти та глибоку пагінацію каталогу.
- **CHECKOUT INTEGRITY 36/36** та **CHECKOUT PRECISION 36/36** успішні. Виробничі збірки трьох frontend пройдені.
- CI запускає весь набір dashboard через `npm test --prefix dashboard`, включно з новими DOM-перевірками.

Перевірки виконано локально. Оновлення не встановлювалося автоматично на робочий VPS. DOM-перевірки не замінюють візуального огляду в реальному браузері після розгортання.
