# ACCORD NICHE v1.15.0 — узгоджене аварійне відновлення

Dashboard **1.83.0**. Наступний пакет аудиту, етап **2.2**: комплект БД, локальних медіа та доменної конфігурації з ключем шифрування.

## Реалізовано

- `deploy/recovery.sh bundle` короткочасно зупиняє процеси запису ACCORD та створює один узгоджений `.tar.gz`. У ньому custom-дамп БД, повний локальний каталог медіа й точна `.env.domains`. Доступна локальна Origin CA-пара включається після перевірки ключа та трьох доменів.
- Контрольні суми перевіряються для всіх частин і файлів медіа. Комплекти приватні (`0600`), публікуються атомарно й не перезаписують один одного. Вони містять секрети та не шифруються автоматично.
- `verify` та `unpack` працюють без Docker і без зміни магазину. Небезпечні шляхи, посилання, спеціальні файли, дублікати та конфлікти структури відхиляються. Розпакування виконується тільки в новий приватний каталог.
- `restore` спочатку перевіряє ключ шифрування та SQL на тимчасовій БД, потім створює новий повний запобіжний комплект. Медіа готуються окремо; БД відновлюється транзакційно, виконуються міграції й перевірки, після чого замінюється каталог медіа.
- При помилці після початку зміни БД процеси запису залишаються зупиненими. Є перевірений шлях повернення повного попереднього стану через запобіжний комплект. PostgreSQL і файлову систему не оголошено єдиною атомарною транзакцією.
- Приватний журнал зберігає фазу, початково активні контейнери та назву запобіжного комплекту. `status` показує його після переривання процесу або перезапуску VPS.
- Docker helper має незмінний ID наявного API-образу, тільки перевірений ACCORD appdata-том, вимкнену мережу, read-only rootfs та скинуті capabilities. ELFAR-томи й ключі інших проєктів не експортуються.
- Dashboard пояснює різницю між дампом лише БД та повним серверним комплектом. Старі команди `.dump` і фонові backup-завдання з v1.14.0 збережені.

## Перевірено

- **397 Python-тестів + 14 підперевірок** — пройдено.
- Реальна тимчасова PostgreSQL: знімок і спільне відновлення замовлень/медіа; повне повернення стану запобіжним комплектом; відмова до змін при іншому ключі або невдалому safety bundle; збереження зупинки після помилки між SQL та медіа і подальше відновлення.
- Файлова система: права зображень для Nginx, відсутність застарілих файлів після заміни, повернення старого каталогу при помилці другого rename; перевірка архівів, private unpack та приватних ключів.
- Справжнє завершення тестового процесу після запису критичної фази не втрачає приватний журнал і шлях запобіжного комплекту.
- OpenSSL: перевірка пари та доменів; сертифікат іншого домену відхиляється.
- Production-збірка dashboard та **55 JS/DOM-тестів** — пройдено.
- Синтаксис Python/shell перевірено. Нові залежності та міграції БД не потрібні; head залишається `c04b19a7e230`.

Docker transport у сценаріях повного відновлення замінено локальним адаптером. Це перевірка реальних SQL і файлових дій, а не підтвердження реального Docker-staging. На робочому VPS нічого не запускалося.

## Оновлення коду

Розпакуйте цей повний вихідний архів у `/opt/accord-niche`, зберігши чинну `.env.domains`, дані та медіа. Звичайне оновлення вже налаштованого shared edge, від root:

```bash
python3 /opt/accord-niche/scripts/connect_elfar_edge.py
```

Команду restore для оновлення коду запускати не потрібно. Інструкція з усіма операціями, місцем на диску, TLS і підготовкою порожнього ACCORD на новому сервері: [RECOVERY_BUNDLE_UA.md](../RECOVERY_BUNDLE_UA.md).

Створення аварійного комплекту — окрема операція з тимчасовою недоступністю дій ACCORD:

```bash
cd /opt/accord-niche
bash deploy/recovery.sh bundle
```

Для TLS типовий каталог — `/etc/accord-niche/tls`. За відсутності локальної пари команда повідомить, що її не включено. Шлях готового комплекту виводиться після успішного створення.

## Наступні етапи

1. Операційний A06: справжнє Docker-staging-відновлення та захищене зберігання комплектів поза VPS.
2. A02: довговічні імпорти XLSX із захистом від повторів і відновленням стану.
3. A04/A10: готовність фонових модулів, керування ними та матриця прав.
4. A08/A11: видимість каталогу та життєвий цикл токенів.
5. Аналітика, оптимізація запитів, UX/SEO та решта історичного QA.

Цей пакет закриває реалізацію наступного кроку в коді, а не весь аудит. Реальний стан VPS та перевірка двох магазинів залишаються окремою операційною роботою.
