# ACCORD NICHE v1.49.1 — порядок у коді й репозиторії

Технічний реліз (етап 4 плану). Поведінка сайту, бота й панелі не змінюється. Міграцій немає.

## Що змінилося

- **Репозиторій бази розбито на частини.** Файл `backend/shop/repo/sql.py` (понад 5 тис. рядків) став пакетом
  `backend/shop/repo/sql/`: окремі модулі для користувачів, каталогу, кошика, замовлень, промокодів, розсилок,
  статистики, налаштувань, обслуговування, чату замовлень, списків бажаного, підтримки, сповіщень і персоналу.
  `SqlRepository` збирається з них, імпорт `from shop.repo.sql import SqlRepository` працює як раніше. Код
  методів перенесено без змін (перевірено порівнянням синтаксичних дерев: 174 методи, 35 функцій).
- **QA-набори** читають код репозиторію через спільну функцію `sql_repository_source()`; тест розсилок за
  розкладом підміняє годинник у модулі розсилок.
- **Описи релізів** перенесено з кореня до `docs/releases/`, тематичні нотатки — до `docs/notes/`. У корені лишився
  тільки `README.md`; посилання оновлено. Виправлено бите посилання в `docs/DEPLOY.md`.
- **Dependabot** (`.github/dependabot.yml`): щотижневі пропозиції оновлень для бекенду, сайту, Mini App, панелі,
  браузерних тестів і GitHub Actions. Нова версія пропонується не раніше ніж через 14 днів після виходу. Сайт і
  Mini App лишаються на React 18 (обмеження розміру бандла).
- **Журнали з панелі** завантажуються з назвою `accord-<сервіс>-….log` замість `elfar-…`.

## Що свідомо лишилося з назвою ELFAR

Спільний edge-проксі з ELFAR, міграція старих ключів у браузері, старі назви резервних копій `elfar-*.dump`,
редиректи старих доменів, змінна `ELFAR_DATA_ROOT` та ключі Redis (`elfar:…` — Redis у ACCORD власний, тож
конфлікту немає). Їх перейменування зламало б сумісність із наявними даними й серверами.

Текст «Замовлення Elfar №…» у коментарі SalesDrive і назву форми «ELFAR — Telegram Bot» за рішенням власника
змінено на ACCORD у [v1.49.2](ACCORD_NICHE_v1.49.2_UA.md).
