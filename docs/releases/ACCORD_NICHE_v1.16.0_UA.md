## Додатково знайдено й виправлено

- **TLS у комплекті відновлення**: на OpenSSL 3.0 (Ubuntu 24.04) `openssl x509 -checkhost` повертає код 0 навіть для чужого домену. Перевірка тепер читає вердикт, тож сертифікат іншого домену справді відхиляється.
- **Біт виконання**: усі `deploy/*.sh` у git були без `+x`, а `certbot-init.sh`, `deploy.sh`, `repair-main-domain.sh` викликали сусідні скрипти як `./x.sh` — на свіжому checkout це «Permission denied». Виклики переведено на `bash ./x.sh`, біт виконання встановлено.
- **Журнал безпеки**: події `security.backup.uploaded` і `security.backup.restore.blocked` записувались, але не були описані в каталозі; мертву `security.backup.restored` прибрано.
- `.env.example` / `.env.domains.example` описують `LOG_LEVEL` і `SALESDRIVE_BACKGROUND_REFRESH_SECONDS`.
- Mini App: inline-відступи профілю перенесено в CSS (вимога дизайн-системи).

## Історичний QA

Застарілі перевірки замінено поведінковими, не послаблюючи контракти: один Alembic head + наявність ревізії в історії (замість жорсткого head); 400 від строгого JSON-middleware; зміна ролі відкликає сесію (новий вхід застосовує нові права); актуальний `promo_discount` під lock; меню з `commerce.js`; ACCORD-назви БД/compose. Набори dashboard, яких не було в `run_all.sh`, додано. Перевірки, що закріплювали старі дефекти (`test_real_transaction_rolls_back_drop_failures`), переписано на правильну поведінку з окремими тестами справжнього відкату.
