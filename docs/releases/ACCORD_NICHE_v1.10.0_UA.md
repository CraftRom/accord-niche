# ACCORD NICHE v1.10.0 — узгоджене оформлення покупки

Виправлено основні сценарії каталогу, товару, кошика, оформлення та історії замовлень. Використовується наявна база даних і той самий атомарний механізм продажу, що й у Mini App та боті.

## Знайдені помилки та результат

## Логіка оформлення

1. Покупець бачить серверний підсумок до погодження з умовами. Сам розрахунок не створює замовлення й не резервує товар.
2. Контактні дані, доставка та згода перевіряються до надсилання. API повторює перевірки незалежно від браузера.
3. Підтвердження використовує показаний `quote_token`. Якщо стан магазину вже змінився, API повертає конфлікт; замовлення не створюється.
4. Повторний запит із тим самим `checkout_key` повертає те саме замовлення. Повторного списання залишку, створення замовлення чи сповіщення менеджеру немає.
5. Якщо відповідь втрачено, можна перевірити збережений ключ або повторити початковий запит. Дані такого запиту зафіксовані, щоб повторення не перетворилося на іншу покупку.

Надісланий запит тимчасово зберігається в `sessionStorage` поточної вкладки для відновлення після перезавантаження. Він містить контактні дані вже підтвердженого покупцем оформлення. Запис очищується після отримання підтвердження, остаточної відмови API або виходу з профілю. Звичайна незавершена форма автоматично не публікується й не надсилається менеджеру.

Усі клієнтські запити мають граничний час очікування. Одночасне початкове завантаження сесії не породжує декілька незалежних запитів CSRF. Для спроби з невідомим результатом мережевий збій відрізняється від остаточної відмови API.

## Каталог, профіль і доступність

Ідентифікатор групи ароматів збережено стабільним. Для переходу на варіант із показаною ціною додано `default_product_id`; він не підмінює ідентифікатор групи. Фільтрація створює окремі результати й не змінює кеш нефільтрованого каталогу. Межі ID товарів відповідають типу БД, тому надмірне значення повертає помилку валідації замість помилки SQL.

У підсумку оформлення можна змінювати кількість і прибирати позиції. Кошик підтримує клавіатурне закриття, утримання фокуса всередині діалогу та повернення фокуса після закриття. Поля мають пов’язані підписи й повідомлення помилок. У профілі усунено дублювання рядків при завантаженні наступної сторінки історії; повторне скасування під час поточного запиту заблоковане.

Гостьова покупка залишається доступною. Google-вхід, бонуси, підтвердження телефону, історія Telegram, ролі dashboard і модерація блогу використовують наявну систему авторизації. Порожній або пробільний підпис профілю не приймається. Надмірна загальна довжина ПІБ перевіряється до запису в БД.

## Сумісність API й розгортання

- Для вебоформлення обов’язкові `checkout_key` і `quote_token`. Попередній штатний frontend їх уже передавав; новий також перевіряє результат перед завершенням покупки.
- Новий `GET /api/web/checkout/status?checkout_key=…` доступний лише поточному покупцеві та його доведеним пов’язаним ідентичностям. Чужий ключ не розкриває даних замовлення.
- Розрахунок вебкошика містить серверні ціни рядків. Формат запитів Mini App і бота не змінено.
- Нових таблиць, міграцій чи змін фінансової історії в цьому релізі немає. Поточний head лишається `c04b19a7e230`.
- Конфігурації доменів, TLS, Compose-мереж і сценарії спільної роботи з ELFAR не змінено.

Оновіть файли лише в `/opt/accord-niche`, зберігши `.env.domains` та наявні дані. Від root:

```bash
python3 /opt/accord-niche/scripts/connect_elfar_edge.py
```

## Перевірки

- 308 Python-тестів і 14 subtests: наявні перевірки, реальні SQL/API-сценарії оформлення, ціни, залишки, повторення запиту, межі доступу й атрибуція.
- 35 JS/DOM-перевірок: 31 для сайту та 4 для політики ролей dashboard. Зокрема перевірено втрату відповіді, відновлення після перезавантаження, повторне підтвердження зміненої суми, помилки полів, незмінність форми після збою, застарілі відповіді довідника й кур’єрську адресу.
- Додаткові набори `CHECKOUT INTEGRITY` і `CHECKOUT PRECISION`: по 36 успішних перевірок.
- Виробничі збірки website, dashboard і Mini App перевірені.

Перевірки виконано локально. Архів не встановлювався автоматично на робочий VPS; реальний Docker Engine і візуальний тест у браузері на сервері в цьому середовищі недоступні. Платіжний еквайринг або нові сторонні інтеграції не підключалися.

Орієнтири для форми й адрес варіантів: [W3C WAI — валідація форм](https://www.w3.org/WAI/tutorials/forms/validation/), [Google Search Central — варіанти товарів](https://developers.google.com/search/docs/appearance/structured-data/product-variants). Це функціональне виправлення магазину; воно не є сертифікацією повної відповідності WCAG чи гарантією пошукової індексації.
