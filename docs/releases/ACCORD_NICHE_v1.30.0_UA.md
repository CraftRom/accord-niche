# ACCORD NICHE v1.30.0 — UI/UX панелі: етап F (матриця ширин і доступності)

Шостий етап за аудитом `ACCORD_NICHE_DASHBOARD_UI_UX_AUDIT_2026-11-18` (UI-014, UI-026). API, права й бізнес-логіка не змінювались; міграцій немає.

## Нова перевірка: `qa/browser-a11y-matrix.mjs`

Проходить 14 сторінок панелі (огляд, замовлення, картка замовлення, каталог, клієнти, підтримка, промокоди, розсилки, блог, журнал, налаштування, команда, копії, інструкції) на ширинах **320, 768 і 1280 px**. На кожній перевіряє:

- рівно один видимий `h1`;
- сторінка не прокручується вбік (таблиці прокручуються у власній рамці);
- **у кожного інтерактивного елемента є доступна назва**, взята з дерева доступності самого Chromium (CDP), а не вгадана з розмітки;
- `id` унікальні, бо від них залежать `label for` і `aria-*`;
- кнопки й поля щонайменше 24×24 px (WCAG 2.2, 2.5.8);
- немає помилок виконання.

Разом 252 перевірки. Набір входить у `qa/run-browser.sh` (окремо: `QA_BROWSER_SUITE=a11y` або `npm run test:a11y` у `qa/`). Клавіатурні сценарії, формулювання для екранних читачів і візуальний огляд лишаються ручними.

## Що матриця знайшла й що виправлено

- **Каталог, 320 px:** кнопки «Експорт / Імпорт / Категорії / Додати» стояли в одному рядку без переносу із заголовком. Заголовок «Каталог» стискався до нульової ширини, «Додати товар» виходив за край екрана. Тепер дії переносяться під заголовок.
- **Каталог, телефон:** підписи категорії, пошуку й сортування ховались через `display: none`, і поля втрачали назви для екранних читачів. Тепер підписи приховані лише візуально. Так само для «Показати» в пагінації.
- **Підтримка:** список «Порядок звернень» не мав назви на жодній ширині.
- **Журнал, 320 px:** рядок «Оновити / Скачати показане / Увесь файл / кожні 10 с» не переносився, і сторінка прокручувалась вбік на 56 px.
- **Сітки `k2/k3/k4` на телефоні** використовували `1fr`, який не стискається нижче природної ширини поля дати й часу. Тепер `minmax(0, 1fr)` на всіх таких сітках.
