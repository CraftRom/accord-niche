# ACCORD NICHE v1.6.4 — виправлення HTTP Error 403 при встановленні TLS

У v1.6.3 connect_elfar_edge.py завантажував кореневі Origin CA з сайту документації Cloudflare. На VPS цей запит повернув HTTP 403 до зміни конфігурації Nginx.

Тепер офіційні публічні RSA/ECC Origin CA включені у deploy/tls/cloudflare-origin-ca.pem. Сценарій бере їх локально, без HTTP-запиту. Походження, відбитки й строк дії задокументовано у deploy/tls/README.md. За потреби --origin-ca дозволяє явно вибрати інший локальний довірений CA-файл.

Збережені перевірки відповідності ключа, строку дії, ланцюжка й обох доменів; TLS verification не вимикається. Порожній CA-файл, HTML замість PEM, приватний ключ, файл понад 128 KiB або сертифікат без CA відхиляються. Системне сховище довіри не змінюється.

Для усунення попереднього 403 достатньо оновити scripts/connect_elfar_edge.py і додати deploy/tls/cloudflare-origin-ca.pem. Повторіть попередню команду з --origin-cert та --origin-key. Наявний .env.domains і файли /etc/accord-niche/tls залиште на місці. Відкат конфігурації після саме цієї помилки не потрібний: вона сталася до запису змін у Nginx/Compose.

Інструкція: docs/ELFAR_ACCORD_SHARED_EDGE_UA.md. DNS ACCORD — Proxied, SSL/TLS — Full (strict). Приватні ключі користувача до архіву не входять.

Перевірки: 236 тестів і 4 subtests пройдено, включно з реальними криптографічними парами, перевіркою офіційних відбитків CA та сценарієм Origin CA з примусово забороненим завантаженням CA. Docker-виклики ізольовані тестовими підмінами. Реальне застосування на VPS у цьому середовищі не виконувалося.
