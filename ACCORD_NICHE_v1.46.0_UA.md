# ACCORD NICHE v1.46.0 — Android-застосунок магазину

Новий окремий проєкт у каталозі [`android/`](android/README.md): нативний застосунок для **Android 12+**
(Kotlin, Jetpack Compose, Material 3), який повністю повторює сайт — каталог, товар, кошик, оформлення,
особистий кабінет, блог і документи — у тих самих кольорах і з тими самими текстами.

## Застосунок

- **Головна:** hero, хіти розпиву, «Перед замовленням», новинки, рекомендації, «Як це працює», контакти й документи.
- **Каталог:** пошук, добірки (усі, хіти, новинки, рекомендуємо, набори), сортування, фільтри в шторці, активні фільтри чипами, нескінченна прокрутка; окремий екран брендів.
- **Товар:** вибір об’єму з ціною на кнопці, ціна за мл, наявність, «Поділитися», схожі аромати.
- **Кошик:** зберігається на пристрої, при кожному відкритті перевіряє ціни й залишки та пояснює зміни в рядку; перехід у Telegram Mini App.
- **Оформлення:** Нова пошта з підказками, кур’єр, оплата, промокод, бонуси, згода з умовами; серверний розрахунок і ідемпотентне підтвердження, яке переживає втрату зв’язку й перезапуск — дублів не буває.
- **Профіль:** вхід через Google, історія з етапами й ТТН, скасування, підтвердження телефону (Telegram або SMS), зв’язування з Mini App.
- **Блог:** статті, коментарі з модерацією, відповіді, власні коментарі зі статусами.
- Світла й темна теми, TalkBack, відкриття посилань сайту в застосунку (App Links).

Застосунок працює з чинним API сайту (`/api/public`, `/api/web`) з тими самими cookies, `Origin` і CSRF.
Замовлення й візити позначені джерелом `accord_android / app`.

## Зміни сервера

1. **Google-вхід із застосунку.** Android Credential Manager видає токен для вебклієнта сайту (`aud`), але з
   Android-клієнтом в `azp`. Сервер тепер приймає такий `azp`, лише якщо його ID перелічено в
   `ACCORD_GOOGLE_ANDROID_CLIENT_IDS`. Аудиторія, як і раніше, мусить бути вебклієнтом сайту; Android-клієнт
   ніколи не приймається як `aud`. Вхід із сайту не змінився.
2. **`/.well-known/assetlinks.json`** на головному домені (`GET /api/public/android/assetlinks.json` через Nginx):
   заява App Links для пакета `ACCORD_ANDROID_PACKAGE` (типово `ua.accordniche.shop`) і відбитків
   `ACCORD_ANDROID_CERT_SHA256`. Поки відбиток не задано, відповідь — `[]`.

Нові змінні описані в `.env.example` і `.env.domains.example`; без них усе працює як раніше.

## Оновлення

```bash
bash deploy/domains.sh check
bash deploy/domains.sh up -d --build
```

Налаштування Google Cloud, підпис релізу та збірка — в [android/README.md](android/README.md).

## Перевірки

- `backend/tests_accord/test_android_app.py`: вебтокен приймається як раніше; Android-`azp` — лише з налаштованим ID; чужий клієнт і Android-клієнт як `aud` відхиляються; `assetlinks.json` порожній без відбитка й коректний із ним; Nginx віддає файл раніше за блокування dot-файлів.
- `android`: юніт-тести логіки (телефон, перевірка форми, обмеження кошика, посилання Mini App, гроші, помилки API, Markdown) і `LiveApiTest` — повний шлях покупця проти запущеного API.
