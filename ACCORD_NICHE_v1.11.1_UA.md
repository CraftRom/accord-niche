# ACCORD NICHE v1.11.1 — виправлення інтерфейсу

Dashboard **1.80.1**. Виправлено конфлікти стилів, поведінку діалогів та неточні стани каталогу й товару.

## Стилі й адаптація

- Стилі нової навігації dashboard завантажуються після базових. Раніше старі правила перекривали темний текст активного пункту світлим. Регресійний тест перевіряє обчислений колір на фактичному CSS виробничої збірки.
- Шапка сайту переходить у компактну навігацію на ширині до 930 px. Зменшено проміжки, узгоджено розміри логотипа та кнопок для вузьких екранів; мобільні кнопки шапки мають розмір 44×44 px.
- Меню й пошук не відкриваються одночасно. Вони мають пов’язані `aria-controls`, закриваються через Escape та при зміні адреси. Після Escape фокус повертається до кнопки відкриття.
- Інформаційне вікно та кошик обмежені висотою доступного екрана й мають внутрішнє прокручування. Усунуто мінімальну висоту списку кошика, яка могла витискати його підсумок за межі низького екрана.
- Довгі назви у кошику й повідомлення помилок переносяться. Збережено читабельні перенесення рядків у повідомленнях сервера.

## Діалоги

Кошик, інформаційні вікна сайту та діалоги dashboard використовують однакові правила фокуса й прокручування:

- фокус утримується у верхньому відкритому діалозі;
- Tab і Shift+Tab проходять лише доступні елементи;
- пропускаються поля вимкнених `fieldset`, приховані та `inert` елементи;
- Escape закриває лише верхній діалог;
- після закриття відновлюється доречний попередній фокус;
- закриття фонового вікна не забирає фокус у верхнього;
- повторне очищення обробників не порушує блокування прокручування іншого вікна.

Інформаційні вікна сайту раніше не мали такого керування. Також усунуто гонку, через яку перший швидкий клік меню міг бути скинутий початковим ефектом компонента.

## Стани даних

Каталог dashboard більше не показує товари попереднього відбору під щойно зміненими фільтрами. Поки новий запит виконується, показано завантаження, а не старі результати та їхню кількість. При повторному оновленні того самого відбору дозволено залишити попередні дані з явною помилкою, якщо сервер тимчасово недоступний.

Після підтвердженої відповіді 404 або 410 сторінка товару сайту очищує застарілі дані й прибирає кнопку покупки. Тимчасовий збій сервера залишає кешовані дані; збережений кошик не очищується через мережеву помилку. Некоректні параметри відбору відрізняються від тимчасової недоступності.

## Перевірки й оновлення

Пройдено **81 JS/DOM-перевірку**: 46 для dashboard та 35 для сайту. Нові сценарії покривають CSS виробничої збірки, фокус, вкладені діалоги, вимкнені поля, Escape, меню, пошук, зміну відбору та видалений товар. Обидві виробничі збірки успішні. `npm test --prefix dashboard` тепер також збирає production CSS перед тестами; дубль цього кроку в CI прибрано.

Серверний код, його тести, міграції, конфігурації TLS, доменів і розгортання звірено з v1.11.0 — вони не змінювалися. Зміни не встановлювалися на робочий VPS. У цьому середовищі виконано DOM-перевірки й перевірку стилів; візуального огляду в реальному браузері не було через обмеження запуску браузера.

Розпакуйте архів у `/opt/accord-niche`, зберігши `.env.domains`. Від root:

```bash
python3 /opt/accord-niche/scripts/connect_elfar_edge.py
```
