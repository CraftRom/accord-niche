# ACCORD NICHE v1.6.5 — транзакції міграцій PostgreSQL

Виправлено падіння migrate на чистій PostgreSQL 16: UnsafeNewEnumValueUsageError для нового orderstatus.ACCEPTED.

Міграція d3a9c05b7e21 додає значення ACCEPTED, а a9d4e77b1c60 переводить у нього старі CONFIRMED замовлення. Alembic запускав усю послідовність в одній транзакції; PostgreSQL не дозволяє використати нове enum-значення до commit. Тепер backend/alembic/env.py задає transaction_per_migration=True в обох режимах. Кожна ревізія та запис її номера фіксуються окремою транзакцією; повторний запуск продовжується після останньої успішної ревізії. Ідентифікатори й SQL історичних міграцій збережені.

Для оновлення v1.6.4 достатньо замінити backend/alembic/env.py файлом цієї збірки. Збережіть .env.domains, томи та файли сертифіката/ключа. Від root:

```bash
cd /opt/accord-niche
bash deploy/domains.sh --docker-edge build migrate api
python3 scripts/connect_elfar_edge.py \
  --origin-cert /etc/accord-niche/tls/origin.pem \
  --origin-key /etc/accord-niche/tls/origin.key
```

Не потрібно видаляти базу, вручну змінювати enum, виконувати alembic stamp або генерувати нові паролі. На стадії зафіксованого збою міграцій зміни проксі ELFAR ще не застосовувалися.

Перевірки: 243 pytest-тести і 4 subtests пройдено. На справжньому тимчасовому PostgreSQL 16.2 у single-user режимі відтворено старий збій, перевірено успішне проходження проблемної послідовності з бази без таблиць і перенесення наявного CONFIRMED замовлення зі збереженням суми. Тести виконують SQL, згенерований Alembic; вони не використовують мережеве підключення asyncpg. CI запускає ці перевірки з окремим PostgreSQL із пакета pgserver, який не додається до production-залежностей.

Додатково всі 39 ревізій скомпільовано для порожньої бази та отриманий SQL виконано на PostgreSQL 16.2 до head bc1a8f723f9d без SQL-помилок. Для двох міграцій, що читають наявні рядки/метадані, при цій компіляції підставлялися порожні результати та відоме ім'я FK початкової схеми. Це додаткова SQL-перевірка, а не повний запуск Alembic через asyncpg. Реальне розгортання на VPS тут не виконувалося.
