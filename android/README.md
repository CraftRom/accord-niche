# ACCORD NICHE — Android-застосунок

Нативний застосунок магазину для **Android 12+** (minSdk 31, targetSdk 35): Kotlin, Jetpack Compose, Material 3.
Повторює сайт [accordniche.pp.ua](https://accordniche.pp.ua/) — той самий каталог, кошик, оформлення,
особистий кабінет, блог і документи — і працює з тим самим API (`/api/public`, `/api/web`), без окремої мобільної версії бекенду.

Зручність: нижня навігація (Головна, Каталог, Блог, Кошик з лічильником, Профіль), світла й темна теми в
кольорах сайту, підписи для TalkBack, зони натискання від 44 dp, відкриття посилань сайту (`/aroma/…`, `/catalog`,
`/blog/…`, `/profile`) прямо в застосунку (App Links).

## Як він говорить із сервером

Застосунок — first-party клієнт того самого сайту:

* сесія та CSRF — ті самі cookies (`__Host-accord_session`, `__Host-accord_csrf`), зберігаються між запусками й не потрапляють у резервні копії;
* кожна зміна (POST/PATCH/PUT/DELETE) надсилає `Origin` сайту і `X-CSRF-Token` — як браузер;
* джерело замовлень і візитів — `accord_android / app`, тож у панелі їх видно окремо від сайту.

## Що налаштувати на сервері (зміни в цьому PR)

1. **Google-вхід.** У Google Cloud (той самий проєкт, що й `ACCORD_GOOGLE_CLIENT_ID`) створіть OAuth-клієнт типу
   *Android*: пакет `ua.accordniche.shop` і SHA-1 сертифіката підпису. Додайте його ID у `.env.domains`:

   ```
   ACCORD_GOOGLE_ANDROID_CLIENT_IDS=1234567890-abc...apps.googleusercontent.com
   ```

   Токен застосунок отримує для вебклієнта сайту (`aud` = `ACCORD_GOOGLE_CLIENT_ID`), а сервер приймає Android-клієнт
   лише як `azp`. Без цієї змінної вхід через Google у застосунку відхиляється, решта працює.

2. **App Links.** Вкажіть SHA-256 сертифіката підпису:

   ```
   ACCORD_ANDROID_PACKAGE=ua.accordniche.shop
   ACCORD_ANDROID_CERT_SHA256=AB:CD:...:EF
   ```

   Сайт віддасть `/.well-known/assetlinks.json`, і Android відкриватиме посилання магазину в застосунку.
   Поки змінна порожня, файл містить `[]` — нічого не заявляється.

Після зміни `.env.domains`: `bash deploy/domains.sh up -d --build`.

## Збірка

Потрібні JDK 17+ і Android SDK (platform 35, build-tools 35). Шлях до SDK — у `android/local.properties`
(`sdk.dir=...`) або `ANDROID_HOME`.

```bash
cd android
./gradlew assembleDebug                 # app/build/outputs/apk/debug/app-debug.apk
./gradlew testDebugUnitTest             # юніт-тести логіки
```

Інша адреса магазину (тестовий стенд): `./gradlew assembleDebug -Paccord.baseUrl=https://staging.example.ua`.

**Реліз.** Створіть `android/keystore.properties` (не комітиться):

```
storeFile=../accord-release.jks
storePassword=...
keyAlias=accord
keyPassword=...
```

і виконайте `./gradlew bundleRelease` (AAB для Google Play) або `assembleRelease`. SHA-1/SHA-256 для пунктів вище:
`keytool -list -v -keystore accord-release.jks -alias accord` (для Play App Signing — з консолі Play).

### Перевірка проти справжнього API

`LiveApiTest` проходить увесь шлях покупця — каталог, фільтри, розрахунок із промокодом, замовлення, повтор без
дубля, історія, скасування, документи, відмова без `Origin` сайту, вихід — через ті самі класи, що й застосунок:

```bash
ACCORD_TEST_API=http://127.0.0.1:8765 ./gradlew testDebugUnitTest
```
